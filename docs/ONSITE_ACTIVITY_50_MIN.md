# Onsite Activity Playbook: 50 Minutes

## Current state

โครงการ web-first greenfield นี้ยังไม่มี production facilitator materials หรือ dashboard Playbook นี้เป็น operational specification สำหรับ review และต้อง pilot เวลา privacy และ accessibility ก่อนใช้งานจริง

## Proposed design

### Shared facilitation principles

- เปิดด้วย safety: กิจกรรมเพื่อ self-reflection ไม่ใช่ diagnosis/official MBTI และไม่ใช้ประเมินผลงาน
- ผู้เข้าร่วมเลือกไม่แชร์ type/คำตอบได้; ใช้ “pass” ได้ทุกช่วง
- facilitator ไม่เห็น raw answers/individual result โดย default; group activity ใช้ self-selected cards หรือ anonymous aggregate ที่ consent แล้ว
- หลีกเลี่ยง “type นี้เป็นคนแบบ…” ใช้ “บางคนอาจมีแนวโน้ม…” และย้ำว่า context/learning เปลี่ยนพฤติกรรมได้
- เตรียม QR, short URL, projector, large-print cards, quiet participation path, captions และ paper/offline contingency

### Preferred flow: assessment before event (50 นาที)

| เวลา | ช่วง | วิธีดำเนินการ / output |
|---:|---|---|
| 0–7 | WHY Framework | purpose, two frameworks separated, limitations, privacy, pass option; quick neutral example |
| 7–15 | Character Reveal | ผู้ใช้เปิดผลบนเครื่องตนเอง; 60-sec silent read; เลือกแชร์เฉพาะสิ่งที่สบายใจ |
| 15–25 | Motivation Matching | จับคู่/กลุ่มเล็ก match scenario cards กับ motivations; reveal ว่าหลายแรงขับนำไปสู่พฤติกรรมเดียวกัน |
| 25–39 | Mixed-team Mission | ภารกิจจำลอง 10 นาที + debrief 4 นาที; assign process roles แบบสมัครใจ ไม่อิง type |
| 39–47 | Personal User Manual | เขียน “ฉันทำงานได้ดีเมื่อ… / เมื่อกดดันช่วยฉันโดย… / อย่าคาดเดาว่า…”; share optional |
| 47–50 | Closing Reflection | one takeaway, consent reminder, delete/export route, feedback link |

Pre-event operations: ส่งลิงก์ 2–3 วันก่อน ระบุ 7–9 นาทีและ deadline ที่ไม่ punitive; reminder ไม่เผยว่าใครได้ผลอะไร; ตรวจ completion เป็น aggregate เท่าที่จำเป็น; มี 9-minute arrival station สำหรับผู้ยังไม่ทำโดยไม่ประกาศชื่อ

### Backup flow: assessment onsite (50 นาที)

| เวลา | ช่วง | วิธีดำเนินการ / output |
|---:|---|---|
| 0–9 | Quiz | QR + concise consent; visible timer แบบไม่กดดัน; support desk; result immediate |
| 9–13 | Reveal | silent reveal + disclaimer; narrative ยังโหลดได้แต่ไม่รอ |
| 13–23 | Motivation Matching | small-group card sort; pass/anonymous mode |
| 23–38 | Team Mission | brief 2, work 10, debrief 3; mixed teams แบบไม่เปิดเผย type บังคับ |
| 38–47 | Personal User Manual | individual 5, optional pair exchange 4 |
| 47–50 | Closing | reflection, feedback, privacy/delete reminder |

Hard-stop operations: นาที 7 แจ้งเหลือ 2 นาทีอย่างสงบ; เนื่องจากเว็บต้องจบ ≤10 นาที ให้ reveal เริ่มจากผู้เสร็จแล้วและมี floater ช่วย resume ผู้ที่มีปัญหา **ห้ามตอบแทน/เดาคำตอบ** หากระบบล่ม ใช้ reflection cards ที่ไม่ assign type และส่งผลภายหลัง แทนการสร้างผลปลอม

### Motivation Matching design

ใช้ scenario workplace-neutral 3–4 ใบ แต่ละใบมีหลาย possible motivations ให้ผู้เล่นเลือก “เหตุผลที่ใกล้ฉัน” แล้วอภิปรายความแตกต่าง เป้าหมายคือแยก behavior จาก motivation ไม่ใช่ทาย type; facilitator guide มี misconception correction โดย expert-reviewed

### Mixed-team Mission design

ภารกิจควรมีการจัดลำดับข้อมูล, สร้างทางเลือก, คำนึงผู้มีส่วนได้ส่วนเสีย และตัดสินใจร่วมกัน เช่นวางแผน community pop-up เชิงสมมติ ไม่มีคะแนนบุคลิก/ผู้ชนะจาก type สังเกต “สิ่งที่ทีมต้องการ” ไม่ label สมาชิก กำหนด roles เช่น timekeeper, inclusion checker, synthesizer แบบสมัครใจและหมุนเวียน

### Measurement and incident plan

เก็บ anonymous pulse: clarity, psychological safety, usefulness, timing และ opt-out comfort ห้ามเก็บ raw result คู่ employee ID เพื่อ analytics Incident owner รับผิดชอบ network fallback, projector privacy, inappropriate disclosure และ deletion request; stop activity หากเกิด harm

## Assumptions

- ห้องมี Wi-Fi/มือถือพอ, projector และ facilitator + floater อย่างน้อยหนึ่งคนใน backup flow
- participant group size และภาษาเอื้อต่อ small groups; ปรับจำนวน facilitator ตาม pilot
- ผู้เข้าร่วม pre-event ได้ใน preferred flow

## Risks

- backup quiz ใช้ 9 นาทีตรงเป้าแต่เหลือ buffer เพียง 1 นาทีจาก hard limit
- peer pressure ทำให้ consent ไม่เป็นอิสระ; screen/projector เผย individual result
- absent/late/network/accessibility needs ทำให้คนถูกทิ้ง
- team grouping ตาม type กลายเป็น labeling หรือ hierarchy

## Open questions

- จำนวนผู้เข้าร่วม, room layout, remote/hybrid, ภาษา และ accessibility accommodations?
- facilitator เห็น completion status ระดับใดโดยไม่ระบุตัว?
- scenario สอดคล้องวัฒนธรรมองค์กรแต่ไม่สะท้อน performance จริงอย่างไร?
- owner สำหรับ incident, support และ deletion request คือใคร?

## Acceptance criteria

- run-of-show รวม 50 นาทีพอดีทั้งสอง flow และมี cue/contingency/hard stop
- consent/pass/private-result ถูกพูดและเขียน; ไม่บังคับเปิดเผย type
- immediate result ทำให้ backup ไม่รอ AI; outage path ไม่ fabricate result
- materials รองรับ keyboard/screen reader/large print/quiet path และผ่าน rehearsal
- pilot อย่างน้อยหนึ่งรอบวัดเวลา ความเข้าใจ และ psychological safety ก่อน launch

## Expert review required

- MBTI/Enneagram expert: WHY, card motivations และ misconception guide
- HR ethics/DPO: voluntariness, facilitator visibility, group aggregation และ incident policy
- accessibility/inclusive facilitation specialist: formats, sensory/cognitive needs และ participation alternatives
